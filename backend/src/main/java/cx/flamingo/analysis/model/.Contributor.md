Represents a GitHub user in the Major League GitHub system, supporting two distinct roles: a ranked contributor or a hiring manager. Serves as the core domain model carrying profile info, location data, and GitHub activity statistics.

## Key Components

| Member | Type | Description |
|---|---|---|
| `Role` | `enum` | Discriminates between `CONTRIBUTOR` and `HIRING_MANAGER` |
| `login` | `String` | GitHub username |
| `type` | `Role` | The user's role in the system |
| `cityId` / `city` | `String` / `City` | Geographic location for leaderboard filtering |
| `nearestTeamId` / `nearestTeam` | `String` / `SoccerTeam` | Closest MLS stadium association |
| `githubStats` | `Map<String, Integer>` | Raw stats map, used directly by `HIRING_MANAGER` |
| `totalCommits`, `score`, etc. | `int` | Individual stat fields used by `CONTRIBUTOR` |
| `getGithubStats()` | `Map<String, Integer>` | Unified stats accessor — builds a map from individual fields for contributors, returns the raw map for hiring managers |
| `lastActive` | `Instant` | Timestamp of most recent GitHub activity |

## Usage Example

```java
// Building a contributor
Contributor contributor = Contributor.builder()
    .login("octocat")
    .name("The Octocat")
    .type(Contributor.Role.CONTRIBUTOR)
    .cityId("nyc")
    .totalCommits(342)
    .starsReceived(120)
    .score(87)
    .build();

// Unified stats access works regardless of role
Map<String, Integer> stats = contributor.getGithubStats();
// => { "score": 87, "totalCommits": 342, "starsReceived": 120, ... }

// Copying and updating via toBuilder
Contributor updated = contributor.toBuilder()
    .score(95)
    .build();
```

> **Note:** `getGithubStats()` is the canonical way to read stats for any `Contributor` — it abstracts over the `CONTRIBUTOR`/`HIRING_MANAGER` storage difference, so callers never need to branch on `type`.
