Represents a U.S. state entity within the Major League GitHub geographic data model, used to group and filter GitHub contributors by state-level location.

## Key Components

| Field | Type | Description |
|---|---|---|
| `id` | `String` | Unique state identifier |
| `name` | `String` | Full state name |
| `code` | `String` | State abbreviation code (e.g., `CA`, `TX`) |
| `displayName` | `String` | Human-readable display label |
| `iconUrl` | `String` | URL to a state icon or flag image |
| `regionIds` | `Set<String>` | IDs of associated regions |
| `regions` | `Set<Region>` | Resolved `Region` reference objects |
| `cities` | `Set<City>` | Resolved `City` reference objects |

**Annotations:**
- `@Data` / `@Builder` — Lombok-generated getters, setters, and builder pattern
- `@JsonInclude(NON_NULL)` — Omits null fields from JSON serialization

## Usage Example

```java
State state = State.builder()
    .id("state-ca")
    .name("California")
    .code("CA")
    .displayName("California")
    .iconUrl("https://example.com/icons/ca.png")
    .regionIds(Set.of("region-bay-area", "region-la"))
    .build();

// Accessing nested references (populated by service layer)
Set<City> cities = state.getCities();
Set<Region> regions = state.getRegions();
```

> **Note:** The `regions` and `cities` fields are reference objects populated at the service layer, not from raw storage. They are omitted from JSON output when null, keeping API responses lean when full resolution is not requested.
