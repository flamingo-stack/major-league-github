Configures and wires the active `CacheServiceAbs` bean based on two runtime properties: `cache.mode` and `cache.implementation`.

## Key Components

- **`CacheMode` enum** — Three operating modes:
  - `read-only` — serves cached data only, no writes
  - `read-write` — normal read/write operation (default)
  - `force-update` — bypasses cache reads to force refresh
- **`CacheImplementation` enum** — Backend storage backend:
  - `redis` — Redis-backed cache (default)
  - `disk` — Local disk-backed cache
- **`cacheService()` bean** — `@Primary` factory method that resolves the correct `CacheServiceAbs` implementation at startup, applies the cache mode to all candidates, then returns the active one.

## Usage Example

Configure via `application.properties` or environment variables:

```java
// application.properties defaults
cache.mode=read-write          // read-only | read-write | force-update
cache.implementation=redis     // redis | disk
```

Override at runtime with environment variables (e.g., in Kubernetes):

```bash
CACHE_MODE=read-only
CACHE_IMPLEMENTATION=disk
```

Inject the resolved service anywhere in the application:

```java
@Autowired
private CacheServiceAbs cacheService; // receives whichever impl CacheConfig selected
```

**Selection logic:**
1. If `cache.mode=read-only` → always returns `ReadOnlyCacheService`, regardless of implementation.
2. Otherwise → returns `RedisCacheService` or `DiskCacheService` based on `cache.implementation`.

Invalid values for either property throw an `IllegalArgumentException` at startup.
