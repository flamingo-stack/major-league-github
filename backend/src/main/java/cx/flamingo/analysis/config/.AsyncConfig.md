Configures two named `ThreadPoolExecutor` beans for asynchronous GitHub contributor data fetching, with graceful shutdown handling on application stop.

## Key Components

| Component | Description |
|---|---|
| `contributorsAsyncExecutorLow` | Low-priority thread pool (`GithuhContributorsLow-` prefix) for background GitHub API calls |
| `contributorsAsyncExecutorHigh` | High-priority thread pool (`GithuhContributorsHigh-` prefix) for time-sensitive GitHub API calls |
| `shutdown()` | `@PreDestroy` hook that gracefully drains both pools on application shutdown |
| `shutdownThreadPoolExecutor()` | Waits up to 10 seconds for pool termination, then forces `shutdownNow()` if needed |

**Configuration property:**

| Property | Default | Description |
|---|---|---|
| `github.api.concurrency` | `10` | Core pool size for both executors |

Both pools share the same shape: core size from `github.api.concurrency`, max size of `100`, queue capacity of `1000`, and a 60-second await-termination window on shutdown.

## Usage Example

Inject either executor by name into any Spring-managed component:

```java
@Service
public class ContributorFetchService {

    private final ThreadPoolExecutor lowPriorityExecutor;

    public ContributorFetchService(
            @Qualifier("contributorsAsyncExecutorLow") ThreadPoolExecutor lowPriorityExecutor) {
        this.lowPriorityExecutor = lowPriorityExecutor;
    }

    public void fetchInBackground(Runnable task) {
        lowPriorityExecutor.submit(task);
    }
}
```

To change the concurrency level, set the property in your environment or `application.yml`:

```yaml
github:
  api:
    concurrency: 20
```
