REST controller that provides type-ahead autocomplete endpoints for filtering options used throughout the Major League GitHub leaderboard UI, including cities, regions, states, programming languages, and MLS soccer teams.

## Key Components

**Endpoints** — all under `/api/autocomplete`:

| Method | Path | Description |
|---|---|---|
| `GET` | `/cities` | Search cities, optionally filtered by `regionId` or `stateId` |
| `GET` | `/regions` | Search regions, optionally filtered by `stateId` or `cityIds` |
| `GET` | `/states` | Search states, optionally filtered by `regionId` or `cityIds` |
| `GET` | `/languages` | Search programming languages by name |
| `GET` | `/teams` | Search MLS soccer teams by name |

**Common Query Parameters:**
- `query` — optional partial-match search string
- `maxResults` — result cap, defaults to `50`
- Cross-entity filters (`regionId`, `stateId`, `cityIds`) narrow results based on related entities

**Dependencies:**
- `CityService`, `StateService`, `RegionService` — geographic filtering services
- `LanguageService` — programming language lookup
- `SoccerTeamService` — MLS team lookup
- All responses are wrapped in `ApiResponse<T>` with a human-readable message

## Usage Example

```java
// GET /api/autocomplete/cities?query=San&stateId=CA&maxResults=10
// Response:
// {
//   "data": [ { "id": "san-francisco", "name": "San Francisco" }, ... ],
//   "message": "Found 3 cities matching the criteria"
// }

// GET /api/autocomplete/languages?query=java&maxResults=5
// GET /api/autocomplete/teams?query=LA
```

All endpoints return `ApiResponse<List<T>>` — never null — making them safe to consume directly in frontend autocomplete components.
