Scheduled Spring service responsible for pre-warming the contributor cache on startup by iterating over all configured programming languages and triggering contributor lookups for each.

## Key Components

| Member | Type | Description |
|---|---|---|
| `runFullCacheCycle()` | `@Scheduled` method | Runs 1 second after startup and repeats every second until the full cycle completes; iterates all languages and fetches contributors via `ContributorController` |
| `contributorController` | Dependency | Invoked to trigger and populate contributor cache entries per language |
| `languageService` | Dependency | Supplies the list of all supported `Language` entities to iterate over |
| `cacheService` | Dependency | Receives `setCacheIsReady(true)` after all languages have been processed, signalling downstream consumers that the cache is warm |

## Usage Example

This service is fully automated — no manual invocation is required. Once registered as a Spring bean, it fires on application startup:

```java
// Triggered automatically by Spring's task scheduler.
// Equivalent manual invocation for testing:
contributorController.getContributors(
    null, null, null, null,
    language.getId(),
    15,
    GithubService.GithubApiPriority.Low
);

// After all languages are processed:
cacheService.setCacheIsReady(true);
```

The `fixedDelay` of 1000 ms means each cycle begins 1 second after the previous one finishes, preventing overlapping cache refreshes. Duration and per-language errors are both logged for observability.

> **Note:** Exceptions during a single language's refresh are caught and logged without aborting the remaining languages, ensuring a partial failure does not prevent the cache from being marked ready.
