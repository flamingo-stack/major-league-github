Orchestrates hiring-related data retrieval by combining GitHub profile information and LinkedIn job postings, with Redis-backed caching for both the hiring manager profile and job openings.

## Key Components

| Component | Description |
|---|---|
| `getHiringManagerProfile()` | Fetches the hiring manager's GitHub profile (via `GithubService`) and returns it as a structured `HiringManagerProfile`, cached under `hiring/manager_profile` |
| `getJobOpenings()` | Retrieves active job postings from LinkedIn (via `LinkedInService`), falling back to three hardcoded Djinni listings if the API call fails or returns empty, cached under `hiring/job_openings` |
| Cache keys | `CACHE_PATH = "hiring"`, `PROFILE_KEY = "manager_profile"`, `JOBS_KEY = "job_openings"` |
| Config properties | `github.username` — the target GitHub account; `github.cache.refresh.interval` — TTL for cached entries |

## Usage Example

```java
// Injected via Spring
@RestController
@RequiredArgsConstructor
public class HiringController {

    private final HiringService hiringService;

    @GetMapping("/api/hiring/profile")
    public Map<String, Object> profile() {
        // Returns { status, message, data: HiringManagerProfile }
        return hiringService.getHiringManagerProfile();
    }

    @GetMapping("/api/hiring/jobs")
    public List<JobOpening> jobs() {
        // Returns LinkedIn jobs, or 3 fallback Djinni listings
        return hiringService.getJobOpenings();
    }
}
```

## Caching Behavior

Both methods follow the same cache-aside pattern: attempt a cache read → on miss, fetch from the upstream source → write result back to cache. The refresh TTL is controlled globally by `github.cache.refresh.interval` and applies to both the profile and jobs entries.
