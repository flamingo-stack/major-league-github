Loads and manages city data from a bundled CSV file, providing filtered lookup and autocomplete capabilities used throughout the Major League GitHub ranking pipeline.

## Key Components

| Member | Description |
|---|---|
| `init()` | `@PostConstruct` hook that parses `data/cities.csv` at startup and assigns each city its nearest MLS team via `SoccerTeamService` |
| `autocompleteCities(query, regionId, stateId, maxResults)` | Filters cities by name substring, region, and/or state; returns results sorted by population descending |
| `getCitiesByStateId(stateId)` | Returns all cities belonging to a given state |
| `getCitiesByRegionId(regionId)` | Returns cities in a region; passing `null` or `"none"` returns all cities |
| `getCityById(id)` | Looks up a single city by its ID |
| `getAllCities()` | Returns the full city list with state data populated |
| `getCitiesByIds(ids)` | Batch lookup by a list of city IDs |
| `getCitiesByNearestTeamId(teamId)` | Returns cities whose nearest MLS stadium belongs to the given team, sorted by population |
| `populateState(city)` | Lazy-populates the `State` object on a `City` using `StateService` |

## Usage Example

```java
// Autocomplete cities in the Pacific region, limited to 10 results
List<City> suggestions = cityService.autocompleteCities(
    "port",       // query
    "pacific",    // regionId
    null,         // stateId (no filter)
    10            // maxResults
);

// Find all cities whose closest MLS team is LAFC
List<City> laFanBase = cityService.getCitiesByNearestTeamId("LAFC");
```

## Notes

- City data is loaded once at startup from `src/main/resources/data/cities.csv`; the pipe character (`|`) separates multiple region IDs in column 7.
- `StateService` is injected `@Lazy` to break a circular dependency between `CityService` and `StateService`.
