Initializes and resolves bidirectional object references between `Region`, `State`, and `City` entities at application startup, replacing stub objects with fully-populated instances.

## Key Components

| Component | Description |
|---|---|
| `init()` | `@PostConstruct` hook that triggers reference population after Spring dependency injection completes |
| `populateReferences()` | Public entry point that orchestrates the full reference population process |
| `populateRegionReferences()` | Resolves states (by code) and cities (by region ID membership) for every region, then replaces the original region with a fully-hydrated `Region` instance via `regionService.updateRegion()` |

**Dependencies injected:**

- `CityService` — provides all cities for filtering by region membership
- `RegionService` — provides all regions and accepts updated instances
- `StateService` — resolves `State` objects from string state codes; also back-populates each state's `regionIds`

## Usage Example

This service runs automatically on startup via `@PostConstruct`. It can also be triggered manually if re-population is needed at runtime:

```java
@Autowired
private ReferencePopulationService referencePopulationService;

// Re-populate all entity references (e.g., after a data reload)
referencePopulationService.populateReferences();
```

**Population flow per region:**

```text
getAllRegions()
  └─ for each Region:
       ├─ stateIds → getStateByCode() → Set<State>  (back-populates state.regionIds)
       ├─ getAllCities() filtered by regionId       → Set<City>
       └─ new Region(..., states, cities) → updateRegion()
```

> **Note:** `getStateByCode()` results are filtered for `null` to safely skip unresolvable state codes without throwing.
