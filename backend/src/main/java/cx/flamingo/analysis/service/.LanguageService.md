Loads and serves the supported programming language list from a bundled CSV file at startup, providing lookup and autocomplete capabilities used throughout the leaderboard API.

## Key Components

| Member | Description |
|---|---|
| `init()` | `@PostConstruct` hook that triggers CSV parsing on startup and logs the loaded count |
| `loadLanguages()` | Reads `classpath:data/languages.csv`, skipping the header row, and builds `Language` objects from each line |
| `autocompleteLanguages(String query, int maxResults)` | Case-insensitive substring search across both `name` and `displayName` fields, capped at `maxResults` |
| `getLanguageById(String id)` | Returns the first `Language` matching the given ID, or `null` if not found |
| `getAllLanguages()` | Returns a defensive copy of the full language list |
| `getDefaultLanguage()` | Returns the Java language entry; throws `RuntimeException` if Java is absent from the CSV |

## Usage Example

```java
@RestController
@RequiredArgsConstructor
public class LanguageController {

    private final LanguageService languageService;

    // Autocomplete: GET /languages?q=java&limit=5
    @GetMapping("/languages")
    public List<Language> autocomplete(
            @RequestParam(required = false) String q,
            @RequestParam(defaultValue = "10") int limit) {
        return languageService.autocompleteLanguages(q, limit);
    }

    // Lookup by ID
    @GetMapping("/languages/{id}")
    public Language getById(@PathVariable String id) {
        return languageService.getLanguageById(id);
    }
}
```

The underlying CSV (`src/main/resources/data/languages.csv`) must have the columns `id,name,displayName,iconUrl` with a header row. Any I/O failure during startup propagates as a `RuntimeException`, preventing the application from starting with an incomplete language list.
