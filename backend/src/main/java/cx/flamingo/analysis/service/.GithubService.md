Orchestrates all GitHub API interactions for Major League GitHub, handling paginated GraphQL queries, rate limiting, token rotation, and parallel contributor fetching across cities.

## Key Components

- **`GithubService`** — Spring `@Service` that coordinates contributor discovery via the GitHub GraphQL API
- **`GithubApiPriority`** — Enum (`Low` / `High`) used to route tasks to separate thread pool executors, controlling query urgency
- **`getTopContributorsIn(...)`** — Fetches and deduplicates contributors across a list of cities in parallel batches, keeping the highest-scoring entry per login
- **`getContributorsForCity(...)`** — Paginates through GitHub GraphQL search results for a single city + language combination, with retry/backoff logic
- **`executeGraphQLQuery(...)`** — Selects the best available GitHub token via `GithubTokenRateManager`, executes the query through a reactive `WebClient`, and delegates response caching to `CacheServiceAbs`

## Usage Example

```java
// Fetch top 50 Java contributors across multiple cities using high-priority threads
List<City> cities = cityService.getCitiesNearStadium(stadiumId);
Language java = languageService.findByName("Java");

List<Contributor> top = githubService.getTopContributorsIn(
    cities,
    java,
    50,
    GithubService.GithubApiPriority.High
);
```

## Error Handling

The service distinguishes between four GitHub API exception types and responds accordingly:

| Exception | Behavior |
|---|---|
| `GithubTimeoutException` | Reduces page size by 2/3 and retries |
| `GithubRateLimitException` | Defers to token manager to switch tokens |
| `GithubTooFastException` | Decrements retry budget and continues |
| `GithubGeneralException` | Logs and continues without decrementing retries |

## Notes

- Concurrency is controlled by the `github.api.concurrency` property (default: `10`)
- Duplicate contributors across cities are resolved by keeping the highest `score` value
- Results are sorted descending by score and capped at `maxResults`
