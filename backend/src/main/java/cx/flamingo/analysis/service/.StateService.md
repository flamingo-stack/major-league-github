Loads and manages US state data from a bundled CSV file, providing lookup and autocomplete functionality for the Major League GitHub backend.

## Key Components

| Member | Description |
|---|---|
| `init()` | `@PostConstruct` hook that triggers CSV loading on startup |
| `loadStates()` | Parses `data/states.csv` from the classpath into `State` objects |
| `autocompleteStates(query, regionId, cityIds, maxResults)` | Filters and ranks states by name/code match, optionally scoped to a region or city list, sorted by total population descending |
| `getStateTotalPopulation(state)` | Aggregates population of all cities belonging to a state via `CityService` |
| `getStateById(id)` | Exact lookup by state ID |
| `getStateByCode(code)` | Case-insensitive lookup by state abbreviation (e.g. `"CA"`) |
| `getAllStates()` | Returns a defensive copy of all loaded states |

## Usage Example

```java
// Autocomplete states matching "cal", within no specific region, max 5 results
List<State> results = stateService.autocompleteStates("cal", null, null, 5);

// Look up a state by its two-letter code
State california = stateService.getStateByCode("CA");

// Look up a state by its internal ID
State byId = stateService.getStateById("us-ca");

// Get all states (returns a defensive copy)
List<State> allStates = stateService.getAllStates();
```

## Notes

- `CityService` is injected with `@Lazy` to break a circular dependency between the two services.
- States are sorted in autocomplete results by **descending total city population**, so more populous states surface first.
- A startup failure to load `data/states.csv` throws a `RuntimeException`, preventing the service from starting in a bad state.
